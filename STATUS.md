## Working conclusions

- **Phase B1-B8 are closed.** Retained identity, locality, static/runtime partition, capability grouping, selected data provenance, semantic disposition, and first-generation design are explicit.
- **Phase B9 passed.** Ninety-six content objects totaling 70,897,301 bytes are hash-correct; the 175-alias immutable generation is published; staged/final validation is 1851/1851 PASS.
- **The existing generation remains immutable and unactivated.** `current` is absent and the promoted launcher is unchanged.
- **Passive B10 startup, topology, 100-second survival, and maps capture passed.** Main, renderer, three zygotes, and one utility process survived with zero GPU process.
- **The passive mapped-selection diagnostic passed.** All 96 selected objects remain hash-correct; the two mapped world-source substitutes also match their selected hashes.
- **The no-RPATH-patch decision is accepted.** `libXau` and `libXdmcp` are selected from exact world paths through retained absolute RPATH edges; duplicate materialization will be removed only in the next generation.
- **The semantic class name for Xau/Xdmcp remains provisional.** Their world-reference behavior is proven, but `PROTECTED_WORLD_SUBSTRATE` is stronger than the evidence.
- **The passive missing Bold font was demand-unmapped.** Selected data requires immutable presence/hash and scenario-correct identity, not universal mapping in every run.
- **`libX11-xcb` is CPU-required X11 bridge/support.** App-local `libvk_swiftshader.so` is an allowed CPU auxiliary mapping and is not GPU-enable evidence.
- **The old exact 125-object mapped-set rule is retired.** Runtime acceptance is class/set based.
- **Clean negative runtime boundaries remain.** Broad-farm, rootfs-provider, and `current` mappings are zero in the passive receipt.
- **The GTK vault-open capability remains open.** Loader-cache/module, icon-theme, and MIME effects are still unproven and must remain separate from the earlier VS Code terminal-font issue.
- **The accepted Debian reference baseline is known.** It is `debian:trixie-slim`, followed by the initial `apt upgrade`, followed by VS Code and its required dependency closure.
- **The suspect debt begins later.** Debian/PRoot fonts and related packages were installed after the VS Code integrated-terminal font issue was discovered.
- **The target philosophy is native font authority.** The glibc/Electron consumers should be pressured to use an explicit fontconfig contract over native Termux-, Android-, or project-owned native-source font bytes rather than a persistent PRoot font installation.
- **The current four Debian-derived selected fonts are historical transition evidence, not an accepted final native-font contract.** Their runtime isolation is useful, but their source authority does not yet satisfy the clarified clean-state target.
- **Do not remove the later font-workaround delta yet.** The post-VS-Code package/configuration delta must first be distinguished from the accepted VS Code dependency closure and from independently justified later packages.
- **Generation identity still needs causal separation before activation.** Current digest mixes content, absolute source/deployment paths, provenance, compiler path, and repository head while not fully identifying application/world/policy composition.
- **Generation rollback is scoped.** A `current` pointer can roll back the selected generation, not the glibc substrate, world providers, application payload, launcher, or user state.
- **Experimental phase scripts are not the final operational surface.** Failure-specific wrappers, hardcoded counts, exact status strings, and absolute device paths remain evidence machinery.
- **The assistant role is auditor/pressure source only.** It may inspect evidence, identify contradictions, set stop lines, and demand proof. It does not implement font selection, operate the device, install/remove packages, or mutate runtime artifacts without an explicit role change.

## Current audit pressure

### P0 — post-baseline delta

Demand evidence that separates:

```text
accepted baseline:
    debian:trixie-slim
    + initial apt upgrade
    + VS Code dependency closure

suspect delta:
    later font workaround packages
    + their automatic dependencies
    + generated fontconfig/cache/configuration products

independently justified later delta:
    packages required by other accepted experiments or capabilities
```

### P1 — native font provider

Demand a bounded design proving:

```text
explicit fontconfig selection
exact native-source font identities
required Latin/mono/bold/Korean-CJK coverage
cache ownership
no rootfs font path, file, or cache authority
```

Candidate classes may be native Termux fonts, Android system fonts visible to the application UID, or project-owned selected bytes acquired from native sources. The auditor does not choose or implement the candidate.

### P2 — cleanup proof

Reject removal until the implementation can show:

```text
VS Code remains functional;
integrated-terminal font behavior is reproduced from native font authority;
accepted later workloads remain intact;
only the later workaround delta is removed;
post-removal caches/configuration are accounted;
clean reconstruction reaches the accepted baseline plus declared non-font additions.
```

### P3 — separate capability tracks

Keep these independent unless evidence joins them:

```text
VS Code terminal font workaround
selected-generation font provider
GTK pixbuf loader/cache
icon-theme data
MIME database
```
