## Working conclusions

- **Phase B1-B8 are closed.** Retained identity, locality, static/runtime partition, capability grouping, selected data provenance, semantic disposition, and first-generation design are explicit.
- **Phase B9 passed.** Ninety-six content objects totaling 70,897,301 bytes are hash-correct; the 175-alias immutable generation is published; staged/final validation is 1851/1851 PASS.
- **The existing generation remains immutable and unactivated.** `current` is absent and the promoted launcher is unchanged.
- **Passive B10 startup, topology, 100-second survival, and maps capture passed.** Main, renderer, three zygotes, and one utility process survived with zero GPU process.
- **The passive mapped-selection diagnostic passed.** All 96 selected objects remain hash-correct; the two mapped world-source substitutes also match their selected hashes.
- **The no-RPATH-patch decision is accepted.** `libXau` and `libXdmcp` are selected from exact world paths through retained absolute RPATH edges; duplicate materialization will be removed only in the next generation.
- **The semantic class name for Xau/Xdmcp remains provisional.** Their world-reference behavior is proven, but `PROTECTED_WORLD_SUBSTRATE` is stronger than the evidence. The successor manifest should use a world X11-support/prefix-provider class rather than inferring substrate ownership from path selection.
- **The passive missing Bold font was demand-unmapped.** Selected data requires immutable presence/hash and scenario-correct identity, not universal mapping in every run.
- **`libX11-xcb` is CPU-required X11 bridge/support.** App-local `libvk_swiftshader.so` is an allowed CPU auxiliary mapping and is not GPU-enable evidence.
- **The old exact 125-object mapped-set rule is retired.** Runtime acceptance is class/set based.
- **Clean negative runtime boundaries remain.** Broad-farm, rootfs-provider, and `current` mappings are zero in the passive receipt.
- **The corrected pre-pixbuf content baseline is provisionally 94 identities.** Eighty-nine selected ELF, four selected fonts, and one generated schema; final membership waits for clean-state font requirements and the interactive GTK capability delta.
- **The GTK vault-open capability remains open.** Inventory found one unusable FHS-path loader cache, twelve rootfs loader modules, two icon-theme indexes, and five MIME database files absent from the B9 manifest.
- **The controlled pixbuf diagnostic remains the correct next runtime discriminator.** Rootfs modules are permitted only as exact diagnostic inputs and cannot become final acceptance authority by inertia.
- **Runtime selection is ahead of supply reproducibility.** The generation avoids rootfs runtime mappings, but the materializer still rechecks absolute source paths in the currently expanded rootfs/prefix.
- **The current rootfs is not yet a clean-state specification.** Its minbase package baseline, manual/automatic delta, font-install history, exact package artifacts, and safe purge set are not recorded.
- **Do not remove rootfs font packages yet.** Existing generation bytes would survive, but successor materialization, current promoted rootfs-backed launchers, and pixbuf source diagnosis may be disrupted before exact supply artifacts and package history are preserved.
- **The four-font set is provisional.** It is a valid observed selected provider, not yet proof of the minimum required Latin/mono/bold/CJK/math coverage for a clean system.
- **Generation identity needs causal separation before activation.** Current digest mixes content, absolute source/deployment paths, provenance, compiler path, and repository head while not fully identifying application/world/policy composition.
- **Generation rollback is scoped.** A `current` pointer can roll back the selected generation, not the glibc substrate, world providers, application payload, launcher, or user state.
- **Experimental phase scripts are not the final operational surface.** Failure-specific wrappers, hardcoded counts, exact status strings, and absolute device paths remain evidence machinery to be consolidated after closure.
- **The rootfs font issue exposes a general supply-layer gap.** Final clean setup should acquire locked artifacts, extract selected bytes, materialize providers, and permit the warehouse to be removed or recreated.
