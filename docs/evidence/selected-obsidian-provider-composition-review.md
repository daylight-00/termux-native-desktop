## Conflict and exclusion policy

The review explicitly excludes:

```text
all Debian-rootfs oracle bytes
static archives
unversioned development aliases
libjpeg.so.8 family and any SONAME-62-to-SONAME-8 alias
Pango oracle concrete suffixes 0.5600.3
unreviewed Pango members including pangoxft
libepoxy EGL or Wayland capability
libtasn1 inclusion before a selected GnuTLS/security profile
any member without an accepted provider decision
```

Ordering is not used to hide conflicts. An unresolved or conflicting SONAME remains a blocker instead of being resolved through `LD_LIBRARY_PATH` order.

## Update and rollback boundary

The composition is reviewed as one logical set. Re-review is required if any of these change:

```text
provider decision or capability scope
member or artifact SHA-256
ELF SONAME or alias target
selected GTK identity ledger
profile inclusion decision
candidate multiplicity or collision set
unresolved gap count or root mapping
```

Because no target exists, rollback is revocation of this composition review and its proposed rows. A future accepted materialized composition must update all coupled Pango family members and aliases atomically and must preserve an immutable previous generation.

## Decision rationale

```text
REVIEWED_BLOCKED_INCOMPLETE
```

The review is complete enough to reject target-manifest generation. It is not complete enough to accept composition.

The next smallest closure tranche is exact official util-linux binding for the accepted GdkPixbuf stack:

```text
libmount.so.1 exact official candidate
libblkid.so.1 exact official transitive candidate
fixed GdkPixbuf JPEG/PNG file and memory matrix with exact map assertions
```

This tranche is selected because the exact project `libjpeg.so.62`, GdkPixbuf, GLib four-member family, and libpng providers are accepted for the fixed decode scope, while the successful probe used non-identical scratch util-linux bytes.
