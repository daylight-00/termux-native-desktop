## Decision 2 — candidate source classes are independently admissible

A proposed non-priority generic object may be reviewed from these source classes only with exact evidence:

```text
Termux-glibc repository artifact and recipe
    candidate; exact non-priority artifact/source binding not yet collected

generic upstream source or distribution artifact
    candidate; requires a reproducible glibc/aarch64 build and integration proof

project-built shared provider
    candidate; requires source lock, toolchain/build receipt, adaptation policy and rollback artifact

native Android provider or adapter
    candidate only when exact ABI/behavior compatibility or an explicit adapter is proved

application-domain supplement
    exception class only after named application-specific ownership beats shared generic ownership
```

The following are not candidate shortcuts:

```text
protected-world leakage;
application-local payload locality;
package-name similarity;
SONAME similarity;
current successful loading;
existing broad-farm selection;
fallback classifier seeds.
```

Exact Termux supply, where later found, still does not automatically become final generic or platform authority. Candidate-source comparison, adaptation, necessity and composition remain separate claims.

## Decision 3 — shared generic ownership is the default review direction

Security/NSS, GTK/GUI, ALSA, udev and printing rows are external shared-capability evidence. Shared generic authority is therefore the default review direction.

This is not final provider selection. It means an application supplement proposal must prove why application-domain ownership is superior to a reusable shared provider and must satisfy `APP-006`.

Protected-world ownership remains reserved for explicitly accepted world identities. The 61 generic rows cannot enter world authority by search-path leakage.

## Decision 4 — capability-specific necessity remains separated

### Security/NSS

Phase B3/B4 establishes a required security capability direction composed from NSS, NSPR, dynamic modules and SQLite support. The exact per-release object set, trust-store policy and source binding remain open.

### GTK/GUI

The 36-object group is dominant static GUI pressure. Package overlap does not authorize one copied GTK runtime tree. Exact X11-only versus Wayland-enabled composition and object source binding remain open.

### Audio and device

ALSA and udev remain distinct direct/static capability directions. Direct dependency pressure is not enough to define permanent source, service/device policy or target inclusion.

### Printing

Printing remains a separate optional capability. It is rejected from the base runtime until the requirement, provider/source set, service policy and rollback boundary are accepted.

### Graphics

`libgbm` static load pressure remains separate from conditional Vulkan feature providers. The Debian and local experiment bytes remain references only; complete Mesa/Freedreno/libgbm authority stays under `AUTH-005`.
